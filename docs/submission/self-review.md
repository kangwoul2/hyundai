# 기획서 내부 평가 (제출하지 않음)

평가일 2026-11-06. 대상: [proposal.md](proposal.md). **점수는 기획서 품질에 대한 내부 평가이며 합격 확률이나 공식 배점이 아니다.** 공식 세부 배점은 공개되지 않았다. 기준선은 항목별 70점, 평균 75점으로 자체 설정했다.

## 1. 점수와 감점 근거

| 심사 항목 | 1차 초안 | 2차 | 최종 | 남은 감점 근거 |
| --- | --- | --- | --- | --- |
| 차량특화성 | 72 | 75 | 75 | 도착 콜백이 Pleos에서 미검증. Vehicle SDK 미사용. 시설 추천 자체는 휴대폰으로도 가능 |
| 창의성 | 63 | 70 | 71 | 아기 동승 주제는 2026-08 사내 해커톤 수상작과 영역이 겹침. 수유실 찾기는 익숙한 기능. 음성 급정차는 아직 계획 |
| 기술 활용성 | 74 | 76 | 76 | 실사용 Pleos SDK는 NaviHelper 하나. 테스트 72건은 제3자 재실행 기록 없음 |
| 사업성 | 58 | 64 | 67 | 직접 사용자 근거 없음. 수익 모델은 가설. 영아기 사용 기간이 짧음. MAU 비율 미측정 |
| 평균 | 66.8 | 71.3 | 72.3 | **기준선 미달: 사업성 70 미만, 평균 75 미만** |

회차별 수정 내용:
- 1차에서 2차: 과장 표기 3곳 정정(내비 목적지 조회, 남은 시간, 추천 이유 예시). "운전석의 보호자는 혼자"라는 문제 문장, 음성 급정차 대화 흐름, 플랫폼 내 신규성 근거, 현대차그룹 입장의 가치, 판단 기준이 있는 검증 계획 추가.
- 2차에서 최종: 인구보건복지협회 조사(2024년 4월, 480명) 근거 추가, "아빠 이용 가능" 조건을 데이터 교체 작업에 연결.

## 2. 강점 3개

1. 실제 Pleos Connect Emulator에서 경유지 포함 경로 요청이 내비 화면에 반영된 증거(로그, 화면, 녹화)가 있다. SDK 문서와 실제 동작의 차이 2건을 발견해 코드에 반영했다.
2. 모든 화면과 영상에 PLEOS, REPLAY, SAMPLE 출처를 표시해 과장이 없다. 심사위원이 검증 범위를 바로 알 수 있다.
3. 서명된 APK, 상태 머신, 어댑터 분리, 단위 테스트 72건과 계측 테스트 4건 기록이 있어 2차 PT 개발 계획이 믿을 만하다.

## 3. 심사상 약점 5개

1. 차량특화성의 핵심인 도착 이벤트 화면 전환이 실제 SDK로 증명되지 않았다.
2. 시설 데이터가 합성 14건이라 추천 품질을 판단할 수 없다.
3. 문제의 크기를 보여주는 직접 사용자 근거가 없다.
4. 시연 영상 초안에서 개발 패널이 앱 화면을 가리고, 자막 줄에 시스템 바 글자가 겹친다.
5. 사내 해커톤 수상작과 주제 영역이 겹쳐 "또 아기 앱"으로 분류될 위험이 있다.

## 4. 결함 분류

| 등급 | 내용 | 1차 제출 영향 |

| CRITICAL | 없음 (1차는 기획서 심사이며 검증 범위를 정확히 표기함) | 제출 가능 |
| MAJOR | 도착 콜백 미검증, SAMPLE 데이터, 사용자 근거 없음 | 점수 상한을 낮춤. 2차 전 해결 필요 |
| MINOR | 영상 품질, 양식 항목과 분량 미확인, 원격 작업 브랜치 잔존 | 정리하면 인상 개선 |

## 5. 작성자가 놓쳤을 반대 관점

- 고속도로에서는 휴게소 간격이 정해져 있어 고를 선택지가 적다. 추천의 가치는 일반도로와 긴 구간에서 더 크다.
- 동승자가 있으면 동승자가 휴대폰으로 찾는 편이 빠르다. 이 앱의 가치는 운전자 단독 이동에 집중된다.
- 현대차가 자체 내비에 수유실 필터를 넣으면 추천 기능의 차별점은 줄어든다. 남는 가치는 도착 이벤트 기반 흐름과 음성 급정차다.
- "아빠 이용 가능" 정보도 시설이 실제로 그렇게 운영하는지와 다를 수 있다. 사용자 응답으로 보정해야 한다.

## 6. 제한된 시간 안에 효과가 큰 수정 3개

1. **영아 보호자 5명 인터뷰 (사용자 수행)**: 사업성을 기준선 위로 올릴 수 있는 사실상 유일한 방법. 결과는 proposal.md 1절과 6.5절에 문장 그대로 넣는다.
2. **시연 영상 재촬영 (사용자 PC)**: 개발 패널을 닫은 상태로 녹화하고, 실제 Pleos 경유지 등록 장면을 앞쪽에 배치.
3. **수유정보 알리미 API 신청 (사용자 수행)**: 신청 사실만으로도 5.3절 일정의 신뢰도가 오른다. 승인되면 SAMPLE을 교체한다.

## 7. 제출 판정

**1차 서류 제출 가능.** 조건: 공식 양식 칸으로 옮긴 뒤 분량 제한 확인, 참가자 동의서 서명. 영상은 초안도 제출 가능하지만 재촬영본이 낫다.

## 8. 추가 검증이 필요한 사실

- 공식 접수양식의 항목 구성과 분량 제한 (DOCX 원본 미확인)
- 참가 부문(대학생 또는 일반) 판정 기준
- Pleos SpeechToText와 TextToSpeech의 에뮬레이터 동작과 권한
- Pleos 내비 모의 주행 방법 (도착 콜백 검증용)
- 수유정보 알리미 API 승인 소요 기간과 이용 조건
- 심사용 GitHub 계정 이름 (비공개 저장소 초대용)
