## 1. 기획 배경과 문제 정의

**운전석의 보호자는 혼자입니다.** 뒷좌석의 아기가 보채기 시작해도 운전자는 휴대폰을 집을 수 없고, 다음 휴게소에 수유실이 있는지도 확인할 수 없습니다. BabyRelay는 이 순간에 필요한 판단을 출발 전과 정차 후로 옮기고, 주행 중에는 차량이 대신 실행하게 만드는 앱입니다.

아기와 차로 1~3시간 이동하는 보호자에게 휴식은 선택이 아니라 일정입니다. 수유와 기저귀 교환을 해야 하기 때문입니다. 그런데 지금은 이 일정을 실행하는 과정이 세 군데에서 끊어집니다.

| 끊어지는 지점 | 지금 보호자가 하는 일 | 생기는 문제 |
| --- | --- | --- |
| 쉴 곳 찾기 | 휴대폰으로 수유실 정보를 따로 검색 | 운전자 혼자면 주행 중에 찾을 수 없다 |
| 내비에 넣기 | 찾은 장소를 차량 내비에 다시 입력 | 출발 후에는 입력할 수 없어 지나치기 쉽다 |
| 도착 후 전달 | 마지막 수유 시각과 챙긴 물품을 기억에 의존 | 아이를 맡길 때 같은 설명을 반복하거나 빠뜨린다 |

- 2025년 출생아는 254,500명으로 전년보다 6.8% 늘었고, 그중 첫째아가 158,700명(62.4%)입니다([국가데이터처 2025년 출생 통계 잠정, 2026-02-25 보도](https://www.newsis.com/view/NISX20260225_0003525439)). 영아와 처음 장거리 이동을 하는 보호자가 해마다 새로 생깁니다.
- 인구보건복지협회가 기혼 남녀 480명에게 물은 조사(2024년 4월)에서, 혼자 아이를 돌볼 때 가장 어려운 점으로 육아 인프라(12.8%)와 수유실 이용(9.7%)이 꼽혔습니다([이투데이 2024-05-11](https://www.etoday.co.kr/news/view/2358838)). 아빠 혼자 아이와 이동하면 "그 수유실을 아빠가 쓸 수 있는가"까지 알아야 합니다.
- 전국 수유시설 3,019곳의 위치와 가족수유실 여부, 아빠 이용 가능 여부는 이미 공공 정보로 공개돼 있습니다([수유정보 알리미](https://sooyusil.com/home/22.htm)). 부족한 것은 정보가 아니라 그 정보를 차가 실행하는 연결입니다.
- **[가설]** 이동 중 위 세 가지 불편의 크기는 아직 직접 측정하지 않았습니다. 6.5절의 검증 계획으로 확인합니다.

## 2. 해결 방안: 주행 상태가 다음 화면을 정하는 돌봄 여정

BabyRelay는 보호자가 출발 전 30초 동안 계획을 세우면, 이후 화면 전환을 차량 내비 이벤트가 결정하는 앱입니다. 운전 중에는 보호자가 아무것도 조작하지 않습니다.

| 단계 | 보호자 행동 | 차량과 앱이 하는 일 | 상태 |
| --- | --- | --- | --- |
| 1. 출발 전 계획 | 다음 휴식 시각(30분~2시간)과 필요한 시설(수유실, 기저귀 교환대)을 버튼으로 고른다 | 목적지와 현재 위치를 기준으로 경로상 후보 2곳을 이유 문장과 함께 보여준다 | [확인] 현재 위치 조회. 내비 목적지 가져오기는 [재현] |
| 2. 경유지 연결 | 후보 하나를 누른다 | Pleos 내비에 경유지로 등록하고, 내비 화면 경로에 경유지가 표시된다 | **[확인]** |
| 3. 주행 중 | 조작하지 않는다 | 다음 휴식 장소와 내비 제공 남은 시간만 표시. 차량 주행 제한 신호에 따라 모든 입력을 잠근다 | [확인] 주행 제한 값 읽기. 남은 시간은 화면으로만 확인 |
| 4. 경유지 도착 | 정차 후 버튼 두 번 | 경유지 도착 이벤트로 돌봄 기록 화면을 연다. 수유, 기저귀, 시설 이용 가능 여부를 시각과 함께 저장 | [재현] |
| 5. 목적지 도착 | 카드를 보여준다 | 목적지 도착 이벤트로 인계 카드를 연다. 마지막 수유와 기저귀 시각, 전달 물품을 한 화면에 요약 | [재현] |

추천 이유는 계산에 실제로 쓴 규칙만 문장으로 보여줍니다. 예: "수유실과 기저귀 교환대 정보 있음 / 출발 후 직선 약 64.8km 지점, 희망 60분 = 약 60.0km(평균 60km/h 가정) / 확인일 2026-10-28". 실제 도로 우회 시간을 모르면 만들어 내지 않고 "직선 기준"이라고 표시합니다. 확인일이 1년을 넘은 시설은 따로 표시합니다.

## 3. 차량특화성: 휴대폰으로는 왜 안 되는가

| 기능 | 휴대폰 앱 | BabyRelay (Pleos Connect) |
| --- | --- | --- |
| 쉴 곳을 차량 내비 경유지로 넣기 | 장소를 공유하거나 다시 입력해야 함 | `requestRouteWithWaypoints`로 내비 경로에 직접 추가 **[확인]** |
| 경유지에 도착한 순간 알기 | GPS 추정, 앱이 꺼져 있으면 모름 | 내비의 경유지 도착 이벤트 `onWayPointArrived` [재현] |
| 목적지 도착 시 다음 행동 제시 | 사용자가 앱을 다시 열어야 함 | `onDestinationArrived`로 인계 카드 자동 표시 [재현] |
| 운전 중 조작 차단 | 앱마다 제각각, 운전 여부를 모름 | 차량 플랫폼의 주행 제한 신호(`CarUxRestrictions`)로 잠금 [확인] |
| 내비가 계산한 남은 시간 | 별도 지도 앱 필요 | `onDrivingInfo`로 표시 (화면으로 확인, 로그 미보존) |

주행과 정차의 역할을 분리했습니다. 주행 중에는 표시만 하고, 선택과 기록은 차량이 주행 제한을 풀었을 때만 가능합니다. 도착 이벤트는 "어디에 왔는가"만 알려주므로 정차의 증거로 쓰지 않습니다. 조작 허용은 오직 플랫폼의 주행 제한 값으로만 판단합니다.

## 4. 창의성: 정보 앱이 아니라 실행 앱

기존 서비스는 각자 한 조각을 맡습니다. BabyRelay는 그 조각을 차량 이벤트로 이어 붙입니다.

| 기존 서비스 | 하는 일 | BabyRelay가 다르게 하는 점 |
| --- | --- | --- |
| 수유실 정보 사이트와 앱 | 시설 검색 | 희망 시각과 경로에 맞춰 2곳만 고르고, 내비에 바로 넣는다 |
| 지도 앱 | 장소 검색, 경유지 추가 | 아기 동승 조건으로 걸러주고, 도착 후 다음 화면을 연다 |
| 육아 기록 앱 | 수유와 기저귀 기록 | 기록 시점을 경유지 도착이 열어주므로 주행 중 입력이 없다 |
| 가족 메신저 | 인계 메모 전달 | 이동 중 기록이 도착 순간 카드로 자동 정리된다 |
| 마이현대 | 차량 원격 제어, 차량 관리 | 아기 동승 이동을 다루는 기능은 확인되지 않았다 |

핵심 발상은 "차가 도착을 알려주면 돌봄의 다음 단계가 열린다"입니다. 공개된 플레오스 앱마켓 앱(2026년 9월 기준 국내 18종)은 주로 내비, 음악, 라디오, 영상 서비스를 차량으로 옮긴 것입니다([현대차그룹 발표](https://www.hyundaimotorgroup.com/ko/news/42dot-pleos-connect-app-market-new-apps)). 내비 이벤트로 화면 흐름을 바꾸는 앱은 공개 자료에서 찾지 못했습니다.

2차 PT까지는 이 발상을 **음성 급정차**로 넓힙니다(5.3절). 계획에 없던 정차가 가장 급하고, 그때 운전자는 화면을 만질 수 없기 때문입니다.

| 순서 | 운전자 | BabyRelay |
| --- | --- | --- |
| 1 | "베이비릴레이, 기저귀" | 요청 인식. 진행 방향 앞에 있는 수유실 후보 중 가장 가까운 1곳 선택 |
| 2 | (듣기) | "약 12km 앞 ○○휴게소에 가족수유실이 있어요. 경유지로 넣을까요?" |
| 3 | "응" 또는 "아니" | 승인하면 내비 경유지 등록. 거절하면 다음 후보를 한 번만 더 제안하고 끝냄 |
| 4 | 경유지 도착 | 돌봄 기록 화면이 열림. 이후 흐름은 계획된 정차와 같음 |

주행 중 화면에는 결과만 표시하고 터치 입력은 받지 않습니다. 음성이 인식되지 않거나 후보가 없으면 "앞쪽에 확인된 수유실이 없어요"라고 말하고 아무것도 등록하지 않습니다.

### 5.4 시설 데이터 처리

수집 스크립트(`tools/collect_facilities.py`)가 원본 CSV나 API 응답을 앱 번들 스냅샷으로 변환하고 품질 지표(좌표 유효율, 중복, 종류 누락, 확인일 분포)를 리포트로 남깁니다. 현재 앱에 들어 있는 시설 14건은 시연용 합성 데이터이며, 앱 화면에 항상 `SAMPLE 데이터`로 표시됩니다. 실제 데이터로 바꿀 때 원본에 없는 속성(예: 운영시간)은 추정해 채우지 않고 "미확인"으로 표시합니다.

## 6. 사업성

### 6.1 대상과 규모

| 구분 | 내용 | 근거 |
| --- | --- | --- |
| 1차 대상 | 생후 3~12개월 아이와 1~3시간 가족 방문이나 여행을 하는 보호자 | [가설] |
| 연간 신규 영아 가구 | 2025년 출생아 254,500명 | [국가데이터처 잠정 통계 보도](https://www.newsis.com/view/NISX20260225_0003525439) |
| 플랫폼 규모 | 플레오스 커넥트는 더 뉴 그랜저부터 적용, 아반떼와 아이오닉 3로 확대, 2030년 약 2,000만 대 탑재 계획 | [머니투데이 2026-04-30](https://www.mt.co.kr/industry/2026/04/30/2026042916243666820), [Pleos 25 발표](https://www.hyundaimotorgroup.com/ko/news/CONT0000000000172880) |
| 예상 MAU 산식 | 플레오스 탑재 차량 수 x 영아 동승 가구 비율 x 설치율 x 월 1회 이상 1시간 이상 이동 비율 | 비율은 출시 후 측정. 근거 없는 수치는 쓰지 않음 |

### 6.2 지속 사용(Retention) 전략

- **계절성이 아닌 생활 주기**: 주말 본가 방문, 명절, 휴가처럼 반복되는 이동에서 쓰입니다. 지난 여정의 휴식 장소와 전달 물품을 다음 계획의 기본값으로 불러옵니다.
- **사용 기간 연장**: 1차는 영아이지만 같은 구조를 "돌봄이 필요한 동승자"로 넓힐 수 있습니다. 반려동물 동반, 임신부, 거동이 불편한 가족은 정차 조건만 다르고 여정 구조는 같습니다.
- **데이터가 좋아지는 구조**: 정차 화면의 "시설 이용 가능/불가" 버튼 한 번이 시설 정보의 최신성을 높입니다. 공공 데이터에 없는 실제 이용 가능 여부가 쌓입니다.

### 6.3 현대자동차그룹 입장의 가치

| 가치 | 설명 |
| --- | --- |
| 앱마켓 다양성 | 이식형 앱 위주인 앱마켓에 "내비 이벤트로 움직이는 차량 전용 앱"이라는 사례를 더한다. 같은 구조를 반려동물 동반, 고령 가족 이동 같은 다른 동승 시나리오로 재사용할 수 있다 |
| 내비 정보 품질 | 경유지 도착 후 "시설 이용 가능/불가" 응답은 내비 장소 정보에 없는 실제 이용 가능 여부다. 사용자 동의를 받아 모으면 가족시설 정보 보강 데이터가 된다 [가설] |
| 가족 고객 경험 | 영아 가구는 해마다 새로 생긴다(2025년 출생아 254,500명). 첫 장거리 가족 이동의 불편을 차량 경험으로 해결하는 것은 가족 고객에게 직접 보이는 차별점이다 |

### 6.4 수익과 협력 방향 [가설]

| 방향 | 내용 |
| --- | --- |
| 시설 운영자 협력 | 휴게소, 쇼핑몰, 공공기관 가족시설의 정확한 정보 제공과 노출 |
| 육아 브랜드 협력 | 도착 인계 카드의 전달 물품과 연계한 제휴 |
| 차량 패키지 | 가족형 차량 옵션이나 커넥티드 서비스 번들 |
| 외부 기기 확장 | 스마트 카시트 클립, 기저귀 센서 제조사와 제휴 시 알림을 계획 트리거로 사용. 단, 안전 판정은 하지 않음 |

### 6.5 검증 계획

| 단계 | 방법 | 판단 기준 |
| --- | --- | --- |
| 출시 전 | 영아 보호자 5명 인터뷰: 최근 1시간 이상 이동에서 어디서 쉬었는지, 사전에 정했는지, 내비에 어떻게 넣었는지, 운전자 혼자였는지 | "사전에 정한다"는 응답이 적으면 음성 급정차를 핵심 기능으로 올림 |
| 출시 후 | 여정 시작 대비 경유지 등록률, 경유지 도착 후 기록률, 시설 이용 불가 응답률, 인계 카드 표시율, 재사용 간격 | 기준값은 1개월 측정 후 설정 |

판단 기준을 미리 정해 둔 이유는, 조사 결과에 따라 기능 우선순위를 바꿀 수 있게 하기 위해서입니다.

## 7. 안전과 개인정보

| 원칙 | 적용 |
| --- | --- |
| 안전 기능으로 오인되지 않게 | 카시트 체결, 아기 탑승 여부, 아기 상태는 판정하지 않는다. Pleos SDK에 해당 신호가 없고, 사용자가 차량이 확인해 준다고 오해하면 위험하다 |
| 운전 중 조작 없음 | 주행 제한 신호가 켜져 있거나 알 수 없으면 선택, 기록, 수정이 잠긴다. 자유 텍스트 입력은 없다 |
| 의료 판단 없음 | 휴식 시각은 보호자가 정한다. 수유 간격을 권하지 않는다 |
| 최소 수집 | 아이 이름, 사진, 연락처, 이동 경로 이력은 저장하지 않는다. 기록은 기기 안에만 두고 서버로 보내지 않는다. 종료 여정은 7일 뒤 삭제한다 |
