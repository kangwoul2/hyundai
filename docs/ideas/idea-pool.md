# 아이디어 후보 — 최종 미선정

최초 정리: 2026-11-05. **이 문서는 후보를 토론하기 위한 것이며 최종 순위·승자를 정하지 않는다.**

## 무엇을 좋은 아이디어로 볼까

좋은 후보는 (1) 실제 사용자 문제가 구체적이고, (2) 자동차 고유 센서 또는 이동 맥락이 핵심이며, (3) 공식 SDK를 통해 구현 가능한 데이터를 확보할 수 있고, (4) 11월 15일 기획서와 12월 초 시연 가능한 작은 범위를 가진다. 추가로 기존 현대차 앱과 겹치지 않는 정도와 위치·개인정보 위험, 사업성을 따진다.

## 1. RainMesh — 자동차가 만들어내는 도로 강수 보조 지도

일기예보의 넓은 지역 단위 정보만으로는 특정 도로에서 실제로 비가 시작했는지 알기 어려운 경우가 있다. 여러 운전자가 동의한 경우, 차량의 와이퍼 사용 신호와 관측 시각을 모아 도로 구간별로 비가 올 가능성을 보조 정보로 표시하는 구상이다. 기상청의 실제 관측값과 비교해 어느 정도 도움이 되는지 검증한다.

- 차량 데이터: Wiper, 가능하다면 Light
- 외부 데이터: 기상청 강수 관측, 시간별 위치(동의 필요)
- 강점: 차량이 움직이는 센서 네트워크가 된다는 독특한 데이터 수집 아이디어
- 리스크: 와이퍼는 비의 정확한 측정기가 아님; 여러 차량 수집이 어려움; 위치 권한·익명화
- 첫 검증: 와이퍼 상태 구독과 에뮬레이터 조작 가능 여부, 1대의 시간 로그 재생

## 2. ParkPulse — 주차 당시 차의 상태와 주변 환경을 함께 기억

비가 많이 오는 날 주차 후 창문이 열려 있는지, 주변에 침수 위험이 있는지 등을 운전자가 놓치기 쉽다. 이 서비스는 정차·주차 당시 차량 상태와 위치, 강수 정보를 결합해 차를 떠나기 전 확인할 정보를 제시한다.

- 차량 데이터: Door, Window, 주차 관련 상태(정확한 메서드 확인)
- 외부 데이터: 강수 예보, 공공 침수 위험 자료
- 강점: 주차라는 구체적 순간에 결합한 차량 특화 경험
- 리스크: 실제 침수를 감지하는 것이 아님; 주차 후 앱이 실행되지 않을 수 있음; 기존 차량 알림과 중복
- 첫 검증: 차량 상태 읽기, 위치 결합 방식, 기존 마이현대 기능 조사

## 3. EcoBudget — 자유 이동에 쓸 수 있는 에너지 예산

전기차 운전자가 현재 배터리로 추가 경유를 해도 무사히 귀가할지 판단하는 데 도움을 주는 구상이다. 단순 잔여 주행거리 대신 차량별 실측 전비와 계획 경로에 따른 차이를 기록하고, 여유 에너지 범위와 불확실성을 보여 준다.

- 차량 데이터: EV SOC, 전비, Odometer
- 외부 데이터: 목적지·경로·날씨(지원 확인)
- 강점: 차량 실측값 기반 오차 보정 가능
- 리스크: 현대차 기존 EV Route Planner와의 기능 중복이 큼; 실제 경로 데이터 가능성 확인
- 첫 검증: SOC/전비 값·단위, 기존 경로 기능과 명확한 차별점

## 4. TireMemory — 타이어 상태를 날짜와 환경에 맞춰 해석

타이어 상태를 하루 한 번 보는 대신, 기온과 주행거리 변화에 따라 수치가 어떻게 바뀌는지 장기 기록한다. 평소 패턴과 다르게 움직이는 경우 사용자가 점검을 고려하도록 안내하는 구상이다.

- 차량 데이터: Tire, Odometer
- 외부 데이터: 일별 기온
- 강점: 정비와 데이터 분석을 연결하는 장기적 유용성
- 리스크: 수치형 공기압 접근이 가능한지 불확실; 고장 여부 자동 진단으로 과장 금지
- 첫 검증: Tire SDK 반환값이 정확히 무엇인지

## 5. SeatFlow — 실제 탑승 좌석에 맞춰 달라지는 이동 경험

누가 아닌 몇 명이 어느 자리에 탑승했는지, 언제 도착하거나 문을 열었는지 같은 이동의 흐름을 사용해 승하차 준비 또는 일정 안내를 제공한다. 예를 들어 여러 좌석 점유 상태와 목적지 도착을 결합해 일행의 하차 전 체크리스트를 제공할 수 있다.

- 차량 데이터: Seat, Door, NaviHelper
- 외부 데이터: 선택적으로 일정/장소
- 강점: 운전자가 입력하지 않아도 차량이 알고 있는 동승 상황 활용
- 리스크: 실제 신원·아이 여부 감지 불가; 기존 사내 해커톤 아이 동승 주제와 차별화 필요
- 첫 검증: 좌석별 점유 정보, 도착 이벤트, 운전자 방해 없는 UI

## 6. CabinAtlas — 차량 실내 쾌적도 실험 기록

같은 공조 온도라도 탑승 인원과 외부 기온에 따라 체감은 달라진다. 차량 공조 설정과 외부 날씨, 탑승자가 정차 중 선택한 쾌적도 평가를 익명 로컬 기록으로 모아 개인화된 쾌적 조건을 설명하는 구상이다.

- 차량 데이터: HVAC, Seat
- 외부 데이터: 날씨
- 강점: 데이터를 직접 모아 규칙을 추정하고 결과를 실험할 수 있음
- 리스크: 실내 온도값 종류 불명확, 초기에는 사용자 기록이 부족함; 자동 공조 제어는 지양
- 첫 검증: HVAC 반환 타입·현재 온도 의미와 정차 시 입력 흐름

## 7. StopMap — 차량이 겪은 정체의 질을 기록

같은 평균속도라도 계속 멈췄다가 출발하는 도로는 피로도가 다르다. 주행 시간과 정차 변화, 구간별 위치를 이용해 사용자가 체감하는 정체 패턴을 기록하고 일반 교통정보와 비교하는 구상이다.

- 차량 데이터: Brake, Odometer, 주행 모드(정확한 가용성 확인)
- 외부 데이터: 교통정보·도로
- 강점: 단순 길안내가 아닌 이동 경험의 다른 측면을 설명
- 리스크: 차속 신호가 불명확하며 GPS·주행 시간만으로 정차를 정확히 판정하기 어려움; 기존 내비와 중복
- 첫 검증: 정차 이벤트 판별 가능 여부와 위치 API

## 후보별 논의용 판단표

| 후보 | 자동차 정보의 중요성 | 데이터 직접 수집 가능성 | 예상 핵심 리스크 | 아직 미검증 |
| --- | --- | --- | --- | --- |
| RainMesh | 높음 | SDK 1대 가능, 다수 차량은 어려움 | 정확도·위치·표본 수 | 예 |
| ParkPulse | 중상 | 중간 | 실시간성·기존 기능 중복 | 예 |
| EcoBudget | 매우 높음 | 중간 | 내장 EV 경로와 중복 | 예 |
| TireMemory | 높음 | 수치형 API에 좌우됨 | 반환 타입·장기간 샘플 | 예 |
| SeatFlow | 높음 | 비교적 명확한 편(추정) | 탑승자 구분·선행 수상작 | 예 |
| CabinAtlas | 중상 | 중간 | 센서 정확도·평가 사용자 수 | 예 |
| StopMap | 높음 | 위치와 이동 구분에 좌우됨 | 차속·개인정보·경쟁 앱 | 예 |

이 표의 표현은 아직 점수나 순위를 뜻하지 않는다. SDK 검증 전에는 확률 또는 합격 가능성을 숫자로 제시하지 않는다.

## 함께 아이디어를 결정할 때의 질문

1. 데이터 수집 실험이 중요한가, 실제 사용자에게 바로 보여 줄 시연의 완성도가 더 중요한가?
2. 한 대의 에뮬레이터로 시연할 것인가, 여러 차량에서 모은 데이터가 핵심인 아이디어도 감수할 것인가?
3. 사용자는 우천·주차·전기차·동승자·차량 관리 중 어느 상황을 가장 깊이 해결하고 싶은가?

이 질문에 답한 후 상위 2~3개만 좁혀 비교한다. **현시점 최종 선택 없음.**
