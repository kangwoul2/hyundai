# BabyRelay 디자인 명세 (Pleos 가이드 반영 + 자체 토큰)

작성 2026-11-05. 모든 스크린샷은 에뮬레이터에서 직접 캡처했다(`docs/design/screenshots/`).
Pleos 공식 가이드와의 일치 여부는 아래 표에서 **공식 확인 / 프로젝트 임시값**을 구분한다.

## 1. 공식 자료에서 확인한 것 (OFFICIAL, 2026-11-05 조회)

| 항목 | 확인 내용 | 출처 |

## 2. 공식 자료에서 **확인하지 못한 것** (UNKNOWN → 프로젝트 임시값 사용)

- 색상 **값(hex)**: 색상 페이지는 값을 이미지로만 제공해 텍스트로 확인할 수 없었다.
- 버튼 크기·반경·타이포그래피 수치: 컴포넌트 페이지의 크기는 SVG 이미지 안에만 있었다. 터치 영역·간격·글자 크기 수치는 "UI Design Guide" 본문에서 확인되지 않았다.
- 디자인 리소스(Figma 등): 공개 페이지에서 접근 가능한 파일을 확인하지 못했다(주행 제한 문서도 "UX Figma 명세는 Playground에 비공개"라고 명시).

→ **아래 토큰은 공식 값이 아니라 BabyRelay 자체 임시 토큰이다.** 공식 토큰 이름 구조(Background/Surface/Text/Informative…)에 대응시켜 교체하기 쉽게 구성했다(`ui/theme/Theme.kt`).

## 3. 자체 임시 토큰

| 토큰 | 다크 | 라이트 | 용도 |
| --- | --- | --- | --- |
| background | #0E0F11 | #F1F3F6 | 앱 배경 |
| surface / surfaceHigh | #181A1E / #23262B | #FFFFFF / #E8EBF0 | 카드 / 비선택 칩·버튼 |
| outline | #3A3F47 | #C9CFD8 | 경계선 |
| text / textSub / textDisabled | #F3F5F8 / #A3AAB5 / #5E646E | #14161A / #545B66 / #9AA1AB | 글자 |
| accent / onAccent / accentSoft | #5AA2FF / #04101F / #1B2A40 | #1F63D6 / #FFFFFF / #DCE8FB | 주 동작·선택(단일 포인트 색) |
| ok / warn / danger | #4CC38A / #F5B547 / #FF6B63 | #14804A / #8F5A00 / #C0322A | 정상·샘플/주의·오류/제한 |

- 그라데이션, 유리 효과, 장식 아이콘, 불필요한 애니메이션을 쓰지 않았다(코드에 애니메이션 없음).
- 상태는 색만으로 구분하지 않는다: 선택은 `✓` + 굵은 글자 + 테두리, 모드/출처는 글자 태그.
- Hyundai 로고·상표를 사용하지 않았다. 앱 아이콘은 자체 벡터 마크이다.

## 4. 크기 체계 (자체 임시값)

| | 일반 | compact (앱 창 높이 < 640dp) |
| --- | --- | --- |
| 터치 높이(주 버튼) | 76dp | 60dp (보조 dense 48dp) |
| 선택 칩 | 68dp | 48dp |
| 여백/간격 | 24dp/14dp | 14dp/8dp |
| 글자(본문 24sp 기준) | 24 / 20 / 18sp | ×0.85 → 약 20 / 17 / 15sp |

**왜 compact가 필요한가(에뮬레이터 실측):** Google AAOS 에뮬레이터 1920×720@240dpi에서 상단 상태바(114px)와 하단 공조 바(144px)를 빼면 앱이 쓰는 창 높이가 약 308dp였다. 처음 구현한 일반 레이아웃은 상단 바와 배너만으로 화면의 절반을 차지해 본문이 잘렸다. 이를 스크린샷으로 확인한 뒤 compact 레이아웃(상태 배너 통합, 라벨 같은 줄 배치, 도착 단계로 전달 물품 이동)으로 수정했다. 1920×1080에서는 추천 2건과 근거가 한 화면에 모두 보인다.

## 5. 화면 구조

| 화면 | 상태 | 핵심 정보(1~2초) | 조작 |
| --- | --- | --- | --- |
| Idle | 세션 없음 | 내비 목적지, "여행 시작" | 큰 버튼 1개 |
| Plan | PLANNING | 목적지·휴식 시각·필요 시설 칩 / 추천 2건과 이유 | 칩 선택, "경유지로 등록", 수동 출발 |
| Trip | DRIVING | "이동 중", 목적지, 다음 휴식 장소와 등록 상태 | 수동 도착(제한 없을 때만) |
| Stop | STOPPED | 정차 장소명, 4개 기록 버튼(✓와 시각) | 기록 4종, "다시 출발" |
| Arrival | ARRIVED | 인계 카드(마지막 수유·기저귀·시설 메모·모드), 전달 물품 | 물품 칩, "확인 완료·종료", "인계 없이 종료" |
| Closed | CLOSED | 종료 사유 | "처음으로" |

상단 공통: 앱 이름 · 4단계 진행 표시 · `SAMPLE 데이터` · `REPLAY · 시뮬레이션 (실제 연동 아님)`/`PLEOS · 내비 연결됨`. 태그를 누르면 개발·시연 패널(출시 사용자용 아님).

## 6. 주행 제한 적용

| 제한 중(또는 알 수 없음) | 잠금 |
| --- | --- |
| 목적지/휴식/시설 변경, 경유지 선택, 수동 출발 | 칩·버튼 비활성 + 상단 빨간 배너 "주행 제한 중 · 선택·기록·인계 수정은 정차 후 사용하세요 (출처: 플랫폼)" |
| 돌봄 기록 입력 4종 | 비활성(기록된 ✓와 시각은 읽기 가능) |
| 인계 카드 편집·종료, 전달 물품 | 비활성(카드 내용은 읽기 가능) |
| 허용 | 상태 읽기, "다시 출발"(상태 기록만 변경), 내비 이벤트에 따른 상태 갱신 |

## 8. 남은 디자인 문제

1. 공식 색·크기 토큰으로 교체(리소스 확보 후).
2. 세로(포트레이트)·분할 창(1:1, 2:1) 화면을 에뮬레이터에서 검수하지 못했다. 코드는 `maxWidth ≥ 840dp && 가로`일 때만 2열이고 그 외는 1열 스크롤이다.
3. compact에서 계획 화면의 추천 2번째 카드는 스크롤이 필요하다(1920×720 기준).
4. 실제 Pleos Connect 에뮬레이터 화면에서의 시스템 바 높이 차이는 `sdk-integration.md`의 Pleos 에뮬레이터 결과 참고.
